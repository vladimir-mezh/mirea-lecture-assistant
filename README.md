# MIREA Lecture Assistant

Desktop-приложение для онлайн-пар РТУ МИРЭА: держит расписание, само открывает нужную
лекцию, следит за её окном и отмечает посещаемость по QR-коду. Основная платформа —
Windows; тот же код запускается на macOS и Linux.

## Установка за минуту

1. Скачайте [**MireaLectureAssistant.exe**](../../releases/latest/download/MireaLectureAssistant.exe)
   и положите его в любую папку, например на рабочий стол. Устанавливать ничего не нужно.
2. Запустите его. Если Windows покажет «Система Windows защитила ваш компьютер», нажмите
   «Подробнее» → «Выполнить в любом случае» (так Windows встречает любую программу из
   интернета без платной подписи).
3. При первом запуске укажите группу, фамилию и имя, затем войдите в MIREA тем же логином и
   паролем, что и на сайте. Чтобы код подтверждения подставлялся сам, укажите почту и
   пароль приложения для неё — подсказка есть прямо в окне входа.

Дальше приложение работает само: закрытие окна прячет его в трей у часов, выход — через
значок в трее. Оно запускается вместе с Windows (выключается в «Настройки → Запуск»),
поднимается само, если упадёт, и само входит в MIREA заново, если вход сломался.

**Обновление.** Когда выходит новая версия, слева в окне появляется кнопка
«Обновить до …»: один щелчок — и приложение само скачает, проверит и установит её и
перезапустится. Вход, пароли, расписание и настройки хранятся отдельно от программы и
при обновлении не теряются. Если файл данных повредится (например, при внезапном
выключении компьютера), приложение восстановит его само; копии данных за последние
5 дней лежат в `%LOCALAPPDATA%\MireaLectureAssistant\backups`.

Что нового — в [CHANGELOG.md](CHANGELOG.md).

## Как это работает

1. **Вход.** Авторизация через MIREA SSO. Пароль лежит в системном хранилище секретов,
   код 2FA читается по IMAP из Gmail, Яндекса, Mail.ru, Рамблера, Microsoft или
   произвольного сервера — из «Входящих» и из «Спама». Истёкшая сессия восстанавливается сама; при обрыве сети рабочая сессия не
   стирается, а вход повторяется с нарастающей задержкой.
2. **Расписание.** Личное расписание приходит из «Пульса» через `pymirea` и
   перечитывается раз в минуту, в том числе во время пары. Обновление сливается с кэшем,
   а не перезаписывает его: «Пульс» опрашивается по одному дню, и сбой одного запроса
   раньше стирал занятия из таблицы.
3. **Поиск комнаты.** Расписание ссылку на вебинар не отдаёт, поэтому приложение само
   находит курс предмета в СДО `online-edu.mirea.ru`, обходит его разделы с вебинарами и
   выбирает строку по предмету, дате, времени и вашей группе. Модули, где названа ваша
   группа или преподаватель этой пары, читаются первыми; адресованные другим группам
   пропускаются, когда комната уже найдена. В СДО приложение при необходимости входит
   само, теми же учётными данными. Ссылку можно задать и вручную — кнопка «Источник».
4. **Лекция.** Открывается в отдельном профиле Chrome/Edge без звука, при желании сразу
   сворачивается. Вкладка проверяется каждые 10 секунд: если её закрыли или соединение
   отвалилось — открывается заново, после трёх неудач перезапускается браузер. Наблюдение
   продолжается и после конца пары по расписанию, пока платформа не покажет фактическое
   завершение; затем вкладка закрывается.
5. **QR.** Кадр снимается прямо со вкладки в разрешении 1920 × 1080 независимо от размера
   окна, поэтому свёрнутое и перекрытое окно сканируется так же. Принимаются только
   attendance-ссылки МИРЭА с UUID-токеном, прочие QR игнорируются молча. Код МИРЭА
   меняется каждые пять секунд: прежний снимается с отправки, как только появился новый.
6. **Отметка.** Валидный QR отправляется автоматически, без подтверждения. При ошибке
   отправка повторяется, при успехе сканирование этой пары прекращается — отметка уже есть.
7. **Резервное сообщение.** Если пять отправок подряд отклонены, в чат MTS Link уходит
   «Фамилия Имя группа» — не больше одного сообщения на занятие. Если за пару не был
   распознан ни один QR, поводом считаются минимум два похожих сообщения других студентов.

## Правила предметов

`AUTO` — открыть саму, `ASK` — спросить, `IGNORE` — не трогать. Режим задаётся один раз
на предмет и действует на все его пары; расписание можно отфильтровать по типу занятия.

## Настройки

Группа, фамилия и имя, время подготовки до пары, интервал сканирования (1–5 с),
источник изображения, компактное окно, звук, сворачивание при открытии и после QR,
закрытие вкладки после пары, качество захвата, резервное сообщение, автоматический вход
и почта для кода. Кнопка «Открыть папку журналов» — там же проверка соединения с почтой.

## Код из письма, когда входишь сам

Если почта для кода настроена, приложение ждёт новые письма МИРЭА через IMAP IDLE: почта
сама сообщает о письме, поэтому компьютер и сеть не нагружаются. Когда приходит код, а
приложение в этот момент само не входит, код копируется в буфер обмена. В журнал буфера
Windows (Win+V) он не попадает и через 90 секунд из буфера стирается. Если впереди окно
браузера установлено расширение (ниже), код сразу вводится в поле кода на странице
входа, даже в неактивной вкладке. Иначе остаётся вставить его Ctrl+V. Обе функции
отключаются в «Настройки → Вход и почта для кода».

## Расширение для своего браузера

Когда вы сами входите на сайт МИРЭА в своём браузере, расширение вводит код из письма
и нажимает «Пропустить» на «Подтверждении через МАКС». Установка: «Настройки → Вход и
почта для кода → Установить в браузер». Приложение само находит браузеры на компьютере
и открывает страницу расширений и папку. Остаётся включить «Режим разработчика» и
перетащить папку на страницу. Когда расширение заработает, приложение это заметит и
покажет в настройках, в каком браузере оно работает.

Обновлять расширение не нужно: приложение кладёт новые файлы при каждом запуске, а
расширение замечает их и перезапускается само. Во время входа на сайт этого не происходит.
«Режим разработчика» в браузере не выключайте: без него браузер отключает такие расширения.
Подходят Google Chrome, Microsoft Edge, Яндекс Браузер, Opera, Brave и Vivaldi;
Firefox — нет.

## MCP для ИИ-клиента (необязательно)

На вкладке «MCP» видны ИИ-клиенты, которые есть на компьютере: Claude Desktop, Claude Code,
Codex, Cursor, Windsurf, VS Code (Copilot), Cline, Gemini CLI, LM Studio. Кнопка
«Подключить» сама скачивает [MCP-сервер](https://github.com/vladimir-mezh/mirea-lecture-assistant-mcp),
включает подключение и прописывает его в настройках клиента. Затем клиент нужно
перезапустить. Через MCP ИИ видит состояние, расписание и настройки, а если разрешить,
может менять настройки и правила предметов. Пароли, коды, QR и чат ему недоступны.
Приложение и MCP обновляются независимо: обновление одного не удаляет другое. Старые версии
MCP удаляются сами, как только ИИ-клиент их отпустит. Подробнее:
[docs/MCP_INTEGRATION.md](docs/MCP_INTEGRATION.md).

## Запуск и разработка

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev,build]"
python -m mirea_lecture_assistant
```

На macOS/Linux окружение активируется через `source .venv/bin/activate`.

```powershell
pytest                                                  # тесты
ruff check src tests scripts                            # разбор
powershell -ExecutionPolicy Bypass -File ./scripts/build.ps1   # сборка Windows
```

Результат сборки — `dist/MireaLectureAssistant.exe`. Официальные сборки делает GitHub
Actions (`.github/workflows/release.yml`): повышение `__version__` в `master` собирает exe
на Windows, проверяет, что он запускается, и публикует релиз с текстом из `CHANGELOG.md`. На macOS/Linux выполните
`pyinstaller --clean --noconfirm MireaLectureAssistant.spec` на целевой системе.
Стартовая строка журнала содержит версию и время сборки: по ней видно, какой именно
бинарник запущен.

Вспомогательные скрипты: `scripts/check_moodle.py` — проверка доступа к СДО и разбор
страницы вебинаров, `scripts/diagnose_login.py` — вход в «Пульс» в той же модели потоков,
что и в приложении.

## Безопасность

Пароль MIREA и пароль приложения почты хранятся в системном хранилище секретов
(Windows Credential Manager / macOS Keychain / Secret Service). Сессия МИРЭА туда не
помещается — Windows ограничивает секрет 2560 байтами, а сессия содержит access- и
refresh-токен, — поэтому она шифруется и лежит в `session.bin` рядом с базой, ключ
шифрования при этом в том же хранилище.

Содержимое QR и attendance-токен на диск и в журналы не попадают: текущий код живёт
только в оперативной памяти до появления следующего, в истории остаётся SHA-256-отпечаток.
Повтор одного токена блокируется на 30 минут. В журналах адреса почты, пароли и коды
маскируются.

## Ограничения

- Microsoft/Outlook официально требует OAuth2 для IMAP; чтение по паролю работает только
  там, где Microsoft разрешает пароль приложения, иначе код вводится вручную.
- `AUTO` открывает найденную комнату, но не нажимает внутренние кнопки платформы:
  для этого нужен устойчивый сценарий под её текущий интерфейс.
- Сессия СДО живёт в профиле браузера; когда Moodle её сбрасывает, приложение входит
  повторно само.
